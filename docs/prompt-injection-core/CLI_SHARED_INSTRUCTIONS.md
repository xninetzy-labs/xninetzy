# Xninetzy continuity — shared client guidance
<!-- id: xninetzy.continuity; version: 2.0.0; scope: shared-client-guidance -->

Read CORE_PROMPT.md and CORE_RULES.md with the selected client adapter.
Use canonical Xninetzy state for owner workflows; the repository is authoritative
for current code. Do not create independent permanent client memory stores.

On resume, identify workspace and objective, retrieve only relevant checkpoints,
and verify that previous assumptions, approvals and pending actions remain current.
If canonical memory is unavailable, report that boundary and retain a repository-local
execution checkpoint when authorized; do not fabricate retrieved context.
Preserve useful decisions, completed operations, evidence references, blockers and
next action. Keep credentials and raw sensitive content out of checkpoints.

For Xninetzy-owned state, discover connected tools and load selected skill resources
progressively. Use native code and file tools for repository work as appropriate.
Tool names may vary by client; never assume a prefix proves availability.
Use code graph discovery where available, then inspect exact source and index gaps.
Use current primary technical sources for version-sensitive integration decisions.
Use relationship traversal when relationships matter; direct lookup for exact facts.
Do not infer a successful write from a narrative result; verify canonical state.
Keep all authentication and consequential-action boundaries in CORE_RULES.md.
