## Trust boundaries and threats

Assets: owner identity/approvals, credentials and institutional sessions, SQLite canonical state, vault and generated files, workflow checkpoints, research provenance, optional indexes, process resources and audit events.

| Boundary / threat | Current evidence | Required mitigation/verification |
|---|---|---|
| Host instructions versus untrusted prompt/tool content | Memory formatter explicitly quarantines records; installed local prompt authority wording is unsafe (`VERIFIED_CODE` in instruction audit) | Host authority preserved; malicious skill/document/output fixtures must not alter permissions |
| Tool invocation versus identity/privilege | Server injects local-owner fields for BaseTools; Streamable HTTP non-loopback is rejected | Verify all callable forms and HTTP origin/host enforcement; remote use requires independent authentication |
| Model planner versus authorization | Separate policy services exist; SEC-01/02 show helper defects | No tool arguments, descriptions, learned rewards or conversational bypass may authorize themselves |
| Approval request versus execution/replay | Stored payload hashes/expiry exist; consumption gap SEC-03 | Atomic exact-payload reservation and uncertain-delivery recovery; concurrency and restart tests |
| Tool inputs versus logs/memory | Core output sanitizer exists; Lightning input fix executed; other previews remain | Structured-key masking, minimization, provenance and retention; synthetic assertions at persistence boundaries |
| Research URL versus local/private network | Scheme, DNS and redirect validation exist | Streamed byte caps and resolver pinning; no private network access from external evidence |
| Repository/vault path versus filesystem escape | Host mapping corrected; artifact allowlist setting exists | Explicit traversal/symlink tests for every write boundary; no blanket claim of safe filesystem behavior |
| Skill catalog versus executable code | Registry labels built-in/user trust by source; resource paths exclude symlinks in discovery | Validate resource read containment, provenance and script content; catalog discovery must not execute scripts |
| External MCP registry versus subprocess | Executable/args/env registry with owner review metadata | Pin provenance, allowlist exact tools/commands, isolate processes where justified; tool descriptions are untrusted |
| Memory/retrieval versus durable truth | Owner-scoped records and quarantine text exist; default memory confidence is heuristic | Correction/supersession tests, contradiction handling and index deletion consistency; poisoned data never becomes policy |
| Graph projections versus canonical state | SQLite/outbox write path and optional projections exist | Correct acknowledgement handling, bounded retries and observable stale projection; no destructive rebuild without approval |
| Workflow versus cross-task isolation | Workflow IDs and chat-scoped queries exist | Verify owner binding for all harness/task reads/writes; no cross-workflow input or checkpoint leakage |
| Dependencies versus local executable trust | Lockfile and optional extras exist | Reproducible base/extra installs and advisory review; no arbitrary third-party scripts/skills installed |
| Background execution versus resource exhaustion | Threaded projection tick and job leases exist | Confirm actual lifecycle wiring, bounded queues/timeouts, cancellation, retry amplification and DB contention |

## Reproduction and verification

The policy reproductions use pure helpers, synthetic strings and `Settings.model_config['env_file']=None` before `get_settings()`, with `MCP_RUNTIME_MODE=container`. They do not execute an Invocable or mutate canonical owner data. Root tests pass explicit temporary paths. Lightning integration writes only a temporary SQLite database and verifies persisted `input_json` and `output_json` exclude synthetic sentinels while retaining normal metadata.

Executed focused commands: `MCP_RUNTIME_MODE=container .venv/bin/python -m pytest tests/interfaces/test_mcp_runtime.py -q` (**17 passed**); isolated pytest for `tests/os/lightning/test_lightning_rl.py`, `test_input_redaction.py`, and `tests/core/test_secret_redaction.py` (**39 passed**); scoped Ruff and `git diff --check` pass. No skipped/xfail changes introduced. Full release suite, remote MCP clients, live providers, backup/restore, container startup and adversarial end-to-end flows remain unverified in this sub-audit.

Minimal-install follow-up: `UV_PROJECT_ENVIRONMENT=/tmp/xninetzy-minimal-audit-env UV_CACHE_DIR=/tmp/xninetzy-audit-uv-cache uv sync --frozen --no-dev --no-editable --reinstall-package xninetzy-mcp` succeeds after narrow dependency and lazy-import fixes. Execution from `/tmp` asserts the imported code is in that installed environment, confirms optional packages are absent, lists all 571 tools and checks actual `datetime_now` content. Final related import/provider/vision/spreadsheet regression: **34 passed**. The lock changes only existing package dependency metadata; no locked version changed. It adds 15 existing transitive distributions to the minimal installation (49 to 64), with no AI/model/provider calls or development-environment installation.

## Rollback and next work

No schema migrations, credentials or production data changed. Roll back only reviewed runtime/redaction source/test hunks, preserving unrelated dirty work. Root fix does not migrate existing out-of-checkout data. If the old sibling store exists, startup deliberately requires a process-environment `MCP_HOST_DATA_DIR`, `MCP_HOST_SQLITE_PATH` or non-container `SQLITE_PATH` selecting the intended store. Newly discovered `.env` settings do not substitute for this explicit choice. Redaction fix does not inspect or sanitize prior logs; any historical-data review needs a separately scoped, privacy-preserving plan. Highest next work: fail-closed policy metadata and independent approval validation, common execution boundaries, reliable workflow status/recovery, graph acknowledgements, then clean-install/deployment checks. Readiness remains **NOT_READY** while these release-blocking questions remain unresolved.
